# Производительность: почему лагает к 5-му раунду

## Диагноз

Дело было не в количестве зомби и не в «тяжёлом рендере».

`update` стоит 0.2–0.6 мс на кадр и почти не растёт от раунда — физика тут ни при чём.
Весь кадр — это `draw`, а внутри него три четверти — свет (`lighting.js`).

А ломалось всё из-за утечки, которая включалась **ровно тогда, когда игрок
включает генератор** — то есть как раз на 3–5 раунде, когда набираются очки.

`glowSprite()` кэшировал спрайты свечения по **строке цвета целиком**. А цвет
ему передавали с альфой, которая каждый кадр новая: у перк-машин это
`0.30 * pulse` от синуса, у взрывов — затухающий `k`. Итог:

| | было |
|---|---|
| новых canvas на кадр | **12** |
| новых `createRadialGradient` на кадр | **12** |
| памяти в секунду | **~46 МБ** |
| удержано через 20 с игры | **~1.9 ГБ** |

Кэш ничего не освобождал, потому что ключи всё время новые. Через минуту-две
после включения света вкладка живёт на сборке мусора — отсюда «лаги к пятому
уровню», которые только усиливаются.

## Что сделано

1. **Свечения пекутся по RGB, яркость едет в `globalAlpha`.** Под `lighter` это
   то же самое, но кэш больше не растёт: 12 спрайтов на кадр → ноль.
2. **Факел игрока** — был клип + новый градиент каждый кадр, теперь запечённый
   сектор, который просто поворачивается.
3. **Виньетка** запекается один раз.
4. **Аддитивный проход свечений ушёл в половинное разрешение.** Он рисовался
   прямо на сцену 800×500 — ~1.4 Мпкс на кадр. Теперь копится на слое света и
   добавляется одним блитом: в 4 раза дешевле, а глазу разницы нет (свечения —
   мягкие пятна).
5. **Текст HUD запекается в спрайты.** ~50 `fillText` за кадр, каждый с
   установкой `font` и тенью. Ключ кэша — RGB без альфы (иначе мигающие
   подсказки пекли бы новый спрайт каждый кадр — ровно та же ловушка, что и со
   свечениями), затухание идёт через `globalAlpha`.

Замер `tools/harness/ablate.mjs` (внахлёст, медиана 3×120 кадров, CPU-canvas
с принудительным сбросом), свет включён:

| | было | стало |
|---|---|---|
| кадр целиком, раунд 5 | 19.69 мс | **14.78 мс** |
| кадр целиком, раунд 20 | ~25 мс | **15.13 мс** |
| проход света | 14.68 мс | **10.80 мс** |
| аддитивные свечения | 9.88 мс | **2.79 мс** |
| отрисовка HUD | 0.974 мс | **0.834 мс** |
| новых canvas/кадр | 12 | **0** |

Картинка не изменилась: худшее отклонение 3/255, пикселей сдвинутых больше
чем на 2/255 — 0.3%, и все они в HUD (текст встал на целые пиксели).

## Настройки

Три новых пункта в меню (`O`), применяются на лету.

**LIGHTING QUALITY — HIGH / MEDIUM / LOW.** Разрешение слоя тьмы: 400×250,
300×188 или 200×125. Раунд 20, кадр целиком:

| качество | слой | кадр |
|---|---|---|
| HIGH | 400×250 | 14.95 мс |
| MEDIUM | 300×188 | 12.79 мс |
| LOW | 200×125 | 11.75 мс |

**AUTO PERFORMANCE — вкл.** Считает, сколько миллисекунд кадр реально тратит
на `update` + `draw` (не настенные часы — на здоровой машине они почти целиком
состоят из ожидания vsync). Если 90 кадров подряд дольше 20 мс — опускает
качество света на ступень; 900 кадров быстрее 11 мс — поднимает обратно.
Потолок — выбор игрока: при MEDIUM ниже LOW не уйдёт. Короткий фриз
(20 кадров по 80 мс) ничего не переключает. На последней ступени
дополнительно выключается погода.

**SIMULATION RATE — NORMAL 60 / HIGH 120.** Шаг физики. Было 120; при просадке
кадров цикл догона превращался в 4 шага за кадр вместо двух — игра удваивала
работу ровно тогда, когда ей тяжело. Теперь по умолчанию 60, и предел догона
снижен с 12 шагов до 6. Стоимость симуляции на секунду игрового времени:
20.4 мс против 28.0 мс — минус 27%. Поведение не меняется (см. тесты ниже).

## Тесты

```bash
cd tools/harness && npm i            # тянет только @napi-rs/canvas
node leak.mjs                        # сколько canvas/gradients создаётся на кадр
node ablate.mjs 5                    # стоимость кадра по частям
node qualityperf.mjs 20              # цена каждой ступени качества и шага
node hudbench.mjs                    # стоимость HUD отдельно
node textchurn.mjs                   # не пекутся ли спрайты текста вечно
node soak.mjs 90                     # полторы минуты игры с боем: ошибки, NaN, память
node shotlight.mjs _a.png && node pixdiff.mjs _b.png _a.png
```

Проверки новых настроек и шага 60 Гц:

```bash
node quality.mjs     # 19 проверок: ползунки, губернатор, потолок, рендер на каждом уровне
node overlay.mjs     # панель настроек из 13 строк влезает в экран, подсветка работает
node step60.mjs      # 60 с на 1/60: 0 зомби в стенах, 0 отсечённых, 0 залипших; то же на 1/120
```

`step60.mjs` сравнивает 1/60 и 1/120 на одном сиде: зомби не оказываются
внутри тайлов, не попадают в отгороженные зоны (что означало бы проход сквозь
стену) и не замирают чаще, чем на 120 Гц. Игрок не продавливается сквозь стены
ни в одном из восьми направлений, лестницы работают.

## Что осталось

- **Слой крови (декали).** ~0.8–1.2 мс за кадр, и он никогда не очищается: за
  долгую сессию карта заливается кровью целиком. Периодически подмывать слой
  или держать лимит на число декалей.
- **Полноэкранные блиты.** Когда слой света уже мал, кадр упирается в блиты на
  800×500: апскейл тьмы, апскейл свечений, декали, виньетка, уровень. На CPU
  это и есть потолок. На GPU всё это почти бесплатно — цифры выше сняты на
  software-рендере и в браузере с GPU будут в разы меньше.
- **Счётчик очков** плавно догоняет целевое значение и тем самым печёт новый
  спрайт текста почти каждый кадр, пока догоняет. Стоит ~0.05 мс/кадра и
  ~0.4 МБ/с мусора — терпимо, поэтому оставлено как есть; если станет жалко,
  квантовать шаг счётчика на время догона.

Главное: **счётчики созданий canvas и утечки переносятся в браузер один в один**,
а миллисекунды — нет. Именно счётчики и были поломкой.
